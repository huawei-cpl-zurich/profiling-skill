# A3 wait-lesson skill assessment

## Outcome

The incremental wait guidance did **not** meet its preregistered usefulness
gate: two strict paired wins, two ties and two losses, rather than the required
four wins out of six. Benefit remains unproven. This is a small qualitative
native A3 pilot, not a statistical result or an A2/A5/Triton generalization.

**Retrospective isolation qualification:** the historical evidence-return path
also copied host-containing compiler intermediates into agent-visible folders.
The trials therefore cannot be presented as a clean blinded optimization
assessment. The recorded scores and failed usefulness gate are retained, not
rescored or promoted. See the isolation audit below; exposure is established,
but exploitation is not.

All twelve agents finished naturally, committed code/reasoning/compact
evidence, and passed the trusted numerical checks. Source-level work-contract
audits rejected two final candidates in each arm. Numerical agreement is not
the same outcome as preserving this experiment's required work.

The [compact assessment ledger](data/a3-wait-paired-assessment04.json) retains
every operational request, retrieved timing samples, scoped pipe rows,
source/commit identities, scores and failures/unavailable results. Agent
branches were not merged. Full isolated repositories, command transcripts,
profile trees and anonymous assessment packets remain in retained campaign
artifacts; this report does not publish their machine-specific routes.

## What was compared

Both arms received the same general optimize/verify/log/commit prompt, trusted
host and neutral tool interface. Each fresh isolated agent saw only its task
and one private profiling-skill snapshot, not prior campaigns, qualification
answers, the other arm or global skills. The task families were inter-core
producer/consumer scheduling, intra-core copy/vector scheduling, and repeated
payload phases with tiny/long timing scopes. Each task had two paired
repetitions, scheduled in four waves of three agents.

- Equal model settings: `gpt-5.6-sol`, low reasoning, 1,200-second total wall
  budget including tool waits, with the final 120 seconds reserved for records.

The comparison isolates the wait-lesson delta, not the whole profiling skill
versus no skill. All unrelated compiler, memory and activity guidance was
identical. Task export, frozen invocation and protocol are retained with the
paired-validation implementation; changing the skill/task during a scored
trial was prohibited.

Default and nondefault native correctness/acquisition gates, compile-error
diagnostics and a real contextless artifact/commit canary passed before
launch. The earlier calibration cohort was excluded because its original
constant recurrence could be collapsed; those artifacts were preserved, not
counted as paired results. The replacement requires seeded input-dependent
recurrence and distinct per-repetition payloads. The skill itself was not
tuned against scored outcomes.

## Blind scoring

This section describes assessor masking, not proof that the optimizer's trusted
host/oracle boundary held. The retrospective audit below found that it did not.

Three fresh contextless, read-only assessors each reviewed four anonymous
participants from one task. They received code, authored reasoning, raw compact
measurements, commands, commit provenance and minimal factual gold, but no arm
identity, pairing or expected benefit. Each dimension is scored 0–2:
acquisition/provenance, interpretation, controlled decisions, and calibration.
Pipe evidence was optional; reading guidance or mentioning a pipe was not
counted as using captured evidence. Sound no-change conclusions were allowed.

Packet QA repaired path-redaction JSON escaping and added initially omitted
selected compact files, committed file lists and the exact trusted check/host
code. Source/results and anonymous aliases stayed identical. The same assessors
corrected factual omissions before unblinding; in particular, the check loop
cycles all declared variants independently of the selected latency variant.
Final anonymous scores were frozen before reading the private mapping
(SHA-256 `249aae78c5bee45f4545b728a9eb1302045fa0d814053537618b97596b872544`).

The four-to-three rewrites preserve the checked mathematical outputs; these
are **instruction/work-contract failures, not numerical kernel failures**.
This distinction matters when interpreting the experiment outside its narrow
fixed-work synchronization question.

One previous-skill phase agent started a replacement request while its original
retained handle was still observation-unavailable, then incorrectly reported
that no resumable handle existed. Another described failed stream-event
requests as pipeline captures. A new-skill intra agent omitted an additional
baseline from its prose/selected summary, although it remains in raw evidence.
These were retained rather than silently repaired in the agents' accounts.
Moving between equivalent physical devices on the same server did not itself
invalidate samples; explicitly false same-device wording was still noted.

## What this teaches about profiling

Three agents actually used pipe captures: new intra-core 1, previous intra-core
2, and new phases 2. Each obtained baseline and final sets of three captures.
The remaining nine did not acquire pipe evidence. No inter-core participant
acquired per-ID wait counters, so this pilot does not demonstrate agent use of
the new per-ID/intra-scalar/IQ/IB distinctions.

The useful code-to-counter observations were narrower:

- **Unchanged work with a scheduling change:** new intra-core 1 retained the
  four-operation recurrence. Reported vector active time was approximately
  7.636667 versus 7.643333 µs. The agent used that near-equality cautiously and
  did not treat separate captures as a simultaneous timeline. Source audit,
  not equal activity alone, establishes retained operations.
- **Less vector work produces less vector activity:** previous intra-core 2
  reported roughly 7.636667 → 6.107778 µs vector active time after removing a
  recurrence operation. New phases 2 reported 221.126663 → 177.215561 µs after
  a three-operation rewrite and barrier changes. These are useful mechanism
  observations, but do not isolate each change's cost or satisfy the fixed-work
  optimization contract. Neither is evidence of capacity saturation.
- **Timing remains the decision evidence:** several source-supported wait moves
  produced noisy or tied timing outcomes. Authors who declined to claim a gain
  were scored positively. Tiny cases, stream-event intervals and task-duration
  captures were not interchangeable; there was no hardware timeline proof.

Thus the pilot supports that agents can acquire and conservatively interpret
some activity evidence. It does not establish that the wait delta improves
reasoning reliably, that pipe acquisition caused the observed choices, or
that aggregate counters establish overlap, critical participants or source PCs.
The tempting inference “more pipe use means better optimization” is not
supported: two pipe-using finals changed required work.

## Runtime, failures and evidence limits

The twelve model trials occupied roughly 73 minutes across four waves and
about 204.5 aggregate agent-minutes. All returned normally with commits; no
trial timed out or received a cohort-level replacement. There were 84
operational requests: 67 timing, nine events, six pipes and two checks. Of 72
admitted jobs, agents retrieved 69 result sets: 57 five-sample task-timing sets
(285 samples), six three-capture pipe sets (18 captures), five seven-sample
event sets (35 samples), and one check-only set. The ledger retains the full
request accounting, including requests that never reached admission.

SSH/preflight, observer and transfer interruptions consumed meaningful budget.
Three original admitted calls remained observation-unavailable in final agent
receipts; this was not proof of kernel failure or still-running device work.
One bounded post-trial observation of each original retained handle subsequently
returned completed/exit0. No job was redispatched or canceled and no additional
result tree was downloaded. That terminal-status reconciliation is recorded
separately and is not retroactively credited as evidence the agents used.
Exit0 alone supplies no additional numerical/profile validation. No score-based
rerun was performed.

BasicInfo samples are profiled task-duration diagnostics, not uninstrumented
latency or phase timelines. No simulator was required or used for the gate.
Native machine instructions were not decoded, and a default `racecheck` request
field was not native sanitizer instrumentation. Missing race/ordering proof
was reported as unknown rather than a demonstrated hazard. In particular,
sampled correctness does not by itself prove arbitrary barrier removal safe.

## Retrospective host/oracle exposure audit

During the integration review, the native evidence archive was found to include
build-tree `.asci`, `.ll`, `.mlir` and related compiler intermediates after
ordinary execution/profiling calls, not only an explicit compiler-IR request.
Some native intermediates contain the trusted host and seeded input/reference
implementation as well as the candidate. Optimizer filesystem isolation did
not protect an oracle returned through this ordinary evidence channel.

A read-only audit of the retained original cohort found **180 host-containing
`.asci` files in ten of twelve agent workspace evidence trees**. These contain
the trusted `main` and expected-output calculations. The other two retained
trees have no such files now; cleanup and incomplete retention mean that this
does not establish that those agents were unexposed. All twelve original
`agent.jsonl` command streams were inspected: none explicitly named an `.asci`,
`.ll`, `.mlir` or host-source file in its recorded command. This narrow negative
finding is **not proof that no artifact was read**, nor a complete access audit.
No observed exploitation is established; the existing work-contract violations
must not be relabeled as deliberate oracle gaming on this evidence.

The preserved two-wins/two-ties/two-losses result remains a historical score of
these recorded trials. It does not establish an uncontaminated causal comparison
of the skill snapshots. Anonymous assessor masking and frozen grading still
describe the scoring process, but cannot repair optimizer information exposure.
No trial was rerun, no score or preregistered criterion changed, and benefit
remains unproven. The ledger carries this qualification separately from outcomes.
The paired-task implementation's fix restricts ordinary native build returns to
build stdout/stderr and leaves native IR unavailable until a device-only producer
role can be established; that fix does not retroactively sanitize this cohort.

## Reproduction and disposition

Use the frozen source/body revisions and equal prompt/model/budget above;
qualify the unchanged native interface and artifact canary, then run fresh
isolated cells in the preregistered wave order. Retain every trial and all
declared samples. Assess anonymously with the four fixed dimensions and the
original critical-claim list; freeze grades before unblinding. Do not select
reruns or edits based on achieved scores. The ledger gives final commit/source
hashes and every request's source identity, operation, variant and raw samples.

Local packet tests, full JSON parsing, original manifest/gate verification,
commit/source equality checks, and skill metadata validation passed. The real
A3 executions provide the remote evidence; no new workload was needed to
write this report. The draft remains unmerged/uninstalled. Further evaluation
or task-design changes require a new accepted plan rather than tuning this
skill against these already-scored examples.

W07 compares unblocked LU rank-one updates with panel16 factorization, block-row triangular solve, and an IEEE FP32 Cube Schur update. This is an independent narrow project implementation of the source-described algorithm. It is not a benchmark of the vendor solver API.

The source lead is `ref://profiling-skill/ascendc/perf-analysis/repos/gitcode-cann-ops-solver#src/sgetrf/sgetrf_kernel.cpp:L215-L365`, with panel elimination in `#src/sgetrf/kernel/getf2.hpp:L71-L139` and the public contract in `#docs/zh/sgetrf.md:L1-L100`. The source supports A2/A3 and excludes950; the measured target must be recorded separately. The native host API includes transfers and synchronization, so its performance does not transfer to this adaptation.

Use the committed nested cases under `cases/wave004/W004-W07-*.json` with `scripts/optimization_pair.py --adapter blocked_lu:factory --case CASE --output NEW_OUTPUT --cache ORACLE_CACHE --provenance PROVENANCE`. Include the Triton example directory on `PYTHONPATH`. `W07.json` retains the complete frozen family, rather than being an individual runner case. Compile all case/arm resources with `blocked_lu.compile_case` before invoking any forward. That function uses Triton compile-only warmup, never a device launch.

The public result is compact FP32 LU with implicit unit L diagonal and zero-based row permutation `p`, satisfying `A[p,:]=L@U`. Input is immutable. Strict positive row diagonal dominance admits the no-pivot identity permutation on CPU before execution. The fixed scientific input has diagonal1.125 and row off-diagonal absolute sum.125. Output tolerance against CPU FP64 elimination is `atol=2e-5, rtol=2e-4`; relative infinity residual is at most2e-5. Nonfinite output fails. LU starts with NaNs before the once-only correctness call, and each API call overwrites all output storage.

Both arms preallocate output once. Every forward includes the complete matrix copy, permutation initialization and all factor stages. The unblocked arm separates L-column writes from rank-one updates with a launch barrier. The blocked panel holds N×16 entries on chip while performing its serial pivots, writes the whole panel once, solves the block row, and applies a global-load IEEE FP32 dot update without TF32. All launches and inter-task gaps belong to the primary device operation span. The span excludes first enqueue and host/profiler overhead and is not application latency. Device busy sum and active union are separate diagnostics.

N not divisible by16 falls back to the same unblocked NPU algorithm. The N4 zero-first-pivot nonsingular guard uses a real CPU dense partial pivot factorization on each call in both arms, returning a nonidentity permutation; it never returns a cached oracle. This correctness-only host fallback is excluded from NPU forward counts and profiling. Nonadmitted profile inputs are rejected. These bounded demonstrations do not provide a general NPU partial-pivot solver.

Scientific protocol: six cached CPU oracle fixtures, one correctness call per arm/case/source version, then exactly ten profiled calls per arm for each of four pairs. Guards have no captures. There are no warmups, autotuning, extra device timing or profile-time output checks. Retain all ten event and device-span samples, exact source/binary hashes, task accounting and PMU rows, including failures. Profiled timing is diagnostic evidence; it is not uninstrumented latency, physical traffic or a roofline claim.

The retained A3 capture passed all fixed cases and guards.

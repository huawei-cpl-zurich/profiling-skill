T06 compares the source compressor's general pooling helper with its ratio-two
row-vector formula, using projected KV and scores as inputs. The general helper
and `_norm_store_1g` come unchanged from triton-ascend-kernels revision
`7acb9c40a6ca827e885d902b7eaee5d45457b230`; license notices are retained beside
the implementation. Both arms own exactly one group per program and preserve
the pooled FP32 → BF16 → FP32 boundary before RMS normalization. Ratio-three
and residual-cache cases launch the identical general kernel on both arms.

This is a prepared pooling component. Projections, cache updates and the public
compressor launcher are outside the measured API. Inputs and private output
storage are reused; allocator costs are excluded. There is no autotuning,
warmup or unprofiled timing. The four main pairs each have one correctness call
and ten profiled API forwards per arm; the two guards have correctness only.
All scientific compilation, resources and linked-code screens precede scientific
CPU oracle generation; all six numeric gates precede any profile capture.

The standalone `compressor_pool.py` CLI is exploratory and accepts a single case
specification, `--output`, `--cache`, `--provenance`, and optional
`--correctness-only`. It validates the host domain before consulting the cache.
It does not perform the controlled collector's all-case codegen/coverage gates.
The prepared API also qualifies compilation before its first numeric launch.

The numerical oracle uses provided FP32 inputs in a CPU FP64 stable softmax,
rounds pooling to BF16, then computes RMS normalization in FP64 and rounds the
result to BF16. Fixed tolerances are atol 0.03125 and rtol 0.015625. Both fallback
pairs additionally require exact BF16 output bits. Output error summaries and
input immutability, nonalias and canary checks run only during correctness.
No extra pooled diagnostic buffer or forward is added; intermediate rounded-pool
differences are unavailable.

The portable result retains every diagnostic event/span sample and supported
raw PMU field. These instrumented operation spans do not establish ordinary
latency, physical DRAM traffic, occupancy, roofline position or full-compressor
throughput. No machine instruction count is inferred from source expressions.

This bounded component deliberately uses common epsilon 1e-6 in both arms and
the CPU oracle. The pinned full Compressor caller uses 1e-20; its full API is
outside this component study and no caller-default claim is made.

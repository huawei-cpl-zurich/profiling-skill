# Native CATLASS FullLoadA residency pair

This example compares forced A reloads with the source kernel's conditional A reuse on A3. It uses native CATLASS C++, not Catlass DSL. The selected source is pinned at `40aced927fdaaa0f3eaa9c6f5c5d859e06392f55`; the retained 68-file closure, notices, original umbrella, common narrowing patch, and hashes are in [l1_a_vendor](l1_a_vendor/manifest.json). This closure builds the selected component; it does not establish that the untouched upstream repository builds with the current SDK.

Both arms use AtlasA2, 24 Cube cores, L1 tile `(128,256,256)`, L0 tile `(128,256,64)`, two B stages, unit flag enabled, and the original `GemmIdentityBlockSwizzle<3,0>` schedule. The before overlay changes only the source `needLoadL1` argument to `true`. The after arm preserves the original conditional. The common umbrella keeps the original primary declarations/defaults and the FullLoadA specialization while removing unused implementation includes. All other retained helpers are byte exact.

The FP16 inputs contain integers in `[-4,4]` divided by 64. Independent CPU FP64 matrix multiplication produces the cached expected result, rounded to FP16 once. At most 1024 products contribute to an output: integer partial sums have magnitude at most 16384, so the dyadic FP32 accumulation is exact. The selected source accumulator is statically verified as FP32. The actual C220 SDK's float-to-half Fixpipe path uses F322F16 with round-to-nearest, ties-to-even. Nonzero output bits and numeric zeros must match; zero sign bits are also retained as a secondary diagnostic.

The frozen collector compiled and inspected all twelve input-only case/arm cells before generating the first expected payload. Six CPU payloads were generated once; each arm passed one correctness call on all six cases before profiling. Four main pairs then ran ten complete prepared API calls per arm, for 80 profiled calls and eight captures. The two guards were correctness-only. There were no warmups, autotuning calls, unprofiled timings, or per-profile input checks.

These are profiler-derived device operation spans over all attributed device tasks, including the source's AIC and empty AIV components. The retained vendor records report one `MIX_AIC` task per API, with Block Num 24, Mix Block Num 48, and both AIC/AIV counters. They are not ordinary uninstrumented latency or a physical memory-traffic measurement. All ten samples, available PMU fields, compiler/source/binary bindings and correctness diagnostics accompany the [result](../../../experiments/optimization-wave009/R12-results.json) and [portable evidence extracts](../../../experiments/optimization-wave009/R12-data/manifest.json). The exact original 1,307-file archive was downloaded and every digest verified; its SHA-256 is `f17454d7c9d7551f695cedcb4a6d60449ec2c991cfe77b8ef2c004ad5dc09523`. Raw traces, native objects, SDK/compiler artifacts, CPU payloads and all failed host attempts remain in that retained archive. The N=256 control has one tile and no A reuse opportunity. Source scheduling predicts 24, 40 and 72 A-reuse transitions for the other main cases; dynamic execution of that branch was not directly observed. Selected candidate device-binary dispatch and numerical correctness were observed. Both arms reserve the same A L1 storage, so these results do not quantify a reservation opportunity cost.

The source layout/resource proof accounts for A's half of L1 (up to 256 KiB), two B stages in the other 256 KiB, L0A 32 KiB, L0B 64 KiB and L0C 128 KiB. Compiler-managed scratch/spills and decoded instruction details remain unknown. The available disassembler did not decode the actual device instructions; host `.so` text is not used as device code evidence.

`Adapter.prepare` validates CPU caller inputs, compiles or verifies the source-bound cache, audits physical tensor storage, allocates private NPU buffers, and initializes the exact C++ `DeviceGemm::Params` through its source headers. Each prepared call launches the source component on the current Torch-NPU ACL stream and reuses its output. Transfers, allocations, source inspection, expected generation, and setup are outside the prepared API. No upstream example `main`, `aclInit`, `aclFinalize`, or device reset runs. Output buffers include canaries; correctness checks immutable inputs, output dtype/shape/layout, nonaliasing and both arms' results. Preparing both arms of all six cases retains 196,340,160 bytes (187.24 MiB) of logical FP16 input/output payload plus canaries. The remaining-profile continuation prepares only its three main pairs. This budget excludes total allocator, runtime, native metadata, and profiler memory; it is not a physical device-memory bound.

`compile_probe(...).compile_only()` is an explicit input-only inspection interface; its `run()` always raises. Compilation is transactional: failed attempts remain retained and cannot become a successful cache entry. The public CLI is exploratory and does not replace the frozen collector. From any working directory, invoke the adapter with an absolute script path, `--case`, `--output`, `--cache`, `--provenance`, and optionally `--build-directory`/`--correctness-only`; use `--inspect-compile --arm before|after` for compile inspection only. Select the named A3 runtime externally through the supported remote-access client.

Three host-only collection defects were retained: CLI test import bootstrap before NPU/oracles; a missing counter directory after the first cached CPU payload but before any native call; and a postcapture binary-identity schema error after all correctness calls and the first twenty profiles. The final repair canonicalized actual AIC/AIV device ELF identities, reanalyzed those twenty unchanged samples, and collected only the sixty previously unattempted calls. No scientific payload, correctness call, or completed profile was replayed. The measured host-interface hashes and the later metadata-only publication hashes are recorded separately.

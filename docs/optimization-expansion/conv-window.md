`conv_contract.py` defines X[B,T,D], W[D,K], nonzero immutable initial[B,D,K-1], and returns Y plus final state. All tensors are contiguous FP16, K=2..8, no bias or activation. Channels do not interact. Weights run oldest to newest. Products and sums use FP32 before FP16 output. The independent CPU oracle uses grouped conv1d; final state must match exactly, while Y uses rtol=atol=.002. This is not the source's complete API: accepted-token indices, padding and duplicate state slots are excluded.

`conv_pairs.py` before performs a timed Triton copy into preallocated output state, then T one-token update launches. After computes immutable virtual windows in parallel and writes final state from the unique token-zero program for each channel tile. No prefix concatenation or other candidate tensor computation happens on CPU. Both complete operations return and check final state; each full call starts from the same immutable input.

The launch count falls from T+1 to one. Explicit state-output writes fall from 2*B*D*(K-1)*(T+1) bytes to 2*B*D*(K-1) bytes. These are source-level logical stores, not measured physical HBM traffic. Both paths allocate the same output/state buffers and no additional adapter workspace. Compiler scratch remains unknown. Before state participates in both convolution reads and shifts; after avoids mutable intermediate windows but rereads immutable samples and weights across token programs. This pair does not promise loading every shared window/weight only once.

Look for a host/token loop, serialized state kernels and repeated state stores. The profiler should show T one-token tasks plus the init task in each complete before forward, and one window task after. Compare full-operation span as well as kernel-duration sum: the many before launches may be dominated by host gaps. PMU memory counters, if supported, can test traffic hypotheses; logical store counts alone cannot establish physical traffic or distance to roofline. T=1 and narrow D test whether the virtual-window indexing overhead matters; retain the observed outcome even if neither countercase regresses.

Two gallery and two private heldouts are predeclared outside the teaching context. CPU tests execute the actual kernels through Triton's interpreter across T=1, T<K-1, K=2/K=8, multiple batches, and channel tails, and test reset across repeated forwards, immutable inputs, final-state rejection, ND audit, zero-launch preparation and binary snapshots. These results establish CPU math only. A3 compilation/resource probes, one correctness per arm, ten complete profiled forwards per arm, kernel inventory and binary retention are still required.

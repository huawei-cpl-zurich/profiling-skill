# Required aligned padding fill (N05)

This standalone native AIV adaptation compares scalar `SetValue` repair with one count-form `Duplicate` per aligned row tail. Both arms copy every padded row GM→UB, write every required positive-zero padding element, and copy every padded row UB→GM. Grid, local capacity, copy commands, bytes, compiler flags and three `PIPE_ALL` barriers are equal. The returned padding is observable; valid FP32 bits, including signed zero, must remain exact.

The vector path admits positive tail lengths only when width and pitch are multiples of eight FP32 elements and pointers are 32-byte aligned. Width 65/pitch 72 uses the same scalar fallback. Width=pitch skips filling. An empty input returns a new empty tensor through `empty_result` without a native launch. Storage is per preparation, with input and output canaries; no cross-launch UB state exists. The conservative software capacity ceiling is 64 KiB, not a hardware capacity claim.

Source evidence is a filtered source-backed pattern, not a claim that an upstream layer normalization operator was accelerated. The actual scalar bodies are `ref://profiling-skill/ascendc/perf-analysis/repos/gitcode-ascend-ops-rec#ascendc/activation/ln_mul/op_kernel/ln_mul_kernel.h:L243-L251` and `#ascendc/mixing/token_mixing/op_kernel/token_mixing.cpp:L229-L239`, revision `e489c0bf6a2d5f2d05b3205fcacc01b62a908b10`, Copyright Huawei Technologies Co., Ltd. 2026, Apache License 2.0. The actual aligned count-form vector body is `ref://profiling-skill/ascendc/perf-analysis/repos/gitcode-cann-ops-nn#norm/layer_norm_v4/op_kernel/layer_norm_v4_transpose.h:L112-L149`, revision `7ed342d28b44b6291aceaf747796028c48d7304c`, Copyright 2025 Huawei Technologies Co., Ltd., CANN Open Software License Agreement Version 2.0. Its README names A2/A3 support. These API patterns informed independently written small kernels; filtered queries `207c5923eed845cf8a9cc1d498401f5f` and `b339eb85c773462fbfc45ecb8dbc2587` retain provenance. Source operator tests do not inspect padding and do not replace the new oracle.

The frozen matrix is `experiments/optimization-wave006/N05.json`. Runtime fixtures are generated once per six scientific payloads, then reused for both arms. Each main arm receives one correctness call followed by exactly ten profiled complete forwards. Guards receive correctness only; the no-tail guard has one native identity component and one host-only empty component per arm. Compilation and actual SDK/ELF AIV checks precede all scientific forwards. Input/output canaries, immutability, nonalias and bitwise output checks happen only during correctness.

Use `aligned_padding:factory` with `scripts/optimization_pair.py`; `compile_all` must first produce the shape-bound libraries and `ALIGNED_PADDING_DIRECTORY` selects them. The normal CLI consumes the frozen case, output/cache locations and provenance JSON. Profiling spans and PMU fields are diagnostic observations, not ordinary latency, physical bandwidth, occupancy or roofline evidence. All slower/equal outcomes are retained.

The A3 run completed all six pairs: 12 native correctness calls, 80 profiled forwards, eight captures, and two additional host-only empty components. Six scientific fixtures were generated once. Mean diagnostic device spans (before→after, microseconds) were 7.712→4.418, 2.286→2.048, 15.744→4.068, and 1.766→1.596. The two larger cases show reduced instrumented spans; the tiny cases retain substantial uncertainty and no universal benefit is claimed. Caller-event latency samples are separately retained and include profiler overhead. Exact samples, hashes and qualifications are in `experiments/optimization-wave006/N05-evidence.json`; raw PMU fields and reports remain bound by the compact manifest.

Actual ELF audits established AIV kind 3 with nonempty vector entries and no Cube entries for all 12 binaries. The installed LLVM objdump recognizes the HIIPU objects but reports unavailable instruction mnemonics. Consequently, scalar/vector lowering remains unconfirmed; function byte sizes are not instruction counts. The first controller's enum-spelling failure happened before fixture generation or native forwards. Its unchanged binaries passed the corrected SDK/ELF audit and were reused without scientific replay.
